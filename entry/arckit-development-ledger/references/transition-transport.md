# 事项状态转换输入与内容透明性

人工或智能体直接调用 `case-transition.mjs`、需要在标准输入与文件之间选择输入方式，或需要处理一次性状态转换载荷时读取本文件。运行时的 `runtime-writeback` 直接传递状态转换对象，不需要临时状态转换文件。

## 输入所有权

`arckit-case-transition/v8` 是账本语义契约。标准输入和 JSON 文件只是命令行传输方式，不是事项状态、证据或运行时执行记录；不满足当前契约的输入直接拒绝。

- 一次性载荷优先通过 `--transition -` 从标准输入提交。
- 需要单独验证时，`validate -` 同样从标准输入读取。
- 调用环境不能传标准输入时，调用方可以在操作系统临时目录创建唯一、仅当前用户可读写的 JSON 文件。
- 临时文件由创建方拥有，必须在成功、失败或取消后的最终清理阶段删除；只有用户明确要求保留调试输入时才能留下并报告路径与敏感性。
- `case-transition.mjs` 不自动删除文件参数，因为它无法判断该文件是一次性载荷还是用户需要保留的复现夹具。
- 不在项目仓库中保存一次性状态转换，不把 `/tmp`、`/private/tmp`、`/var/folders` 或其他临时路径写入证据、事项、项目、迭代或交接。
- 需要过程审计时使用运行时宿主在项目目录外管理的运行结果、活动与事件。桌面端只向事项轮次写入 `arckit-runtime://runs/RUN-...` 不透明引用；不要把宿主绝对路径或临时输入提升为证据。

新增持久文件证据时按[事项结果验证证据归档](case-evidence.md)选择已有载体或事项证据目录；提交用的临时载荷不进入证据目录。

## 内容透明性

状态转换中的命令、正则、路径、引号、反斜杠、换行、Unicode 和 `$` 序列都是不透明数据。渲染器必须原样保存，不能把它们解释为模板、替换字符串、命令解释器或 Markdown 控制语义。

- 不得为了通过序列化、渲染或索引校验而改写真实命令或证据。
- `Structured Record` 写入前必须先渲染到内存，重新解析 JSON，并确认结果与目标记录深度一致。此章节名由脚本正则直接解析，必须保留原文；不能将生成文档中的 `## Structured Record` 改成中文。
- 试运行和正式应用必须共用同一渲染路径；试运行还要只读预检事项索引的现有输入。
- 回归测试至少覆盖 `$'`、`$&`、``$` ``、`$$`、`$1`、引号、反斜杠、换行和 Unicode 的逐字往返。

## 失败处理

输入解析、往返检查、索引预检或正式提交任一步失败时停止写回并报告原始错误。不得绕过校验、手工改账本或用“等价”证据替换原始事实。正式提交开始后的失败继续由账本原子回滚恢复；运行时宿主记录独立于权威账本提交并由宿主自己的生命周期管理。
