# 目标分析与执行授权

开始、恢复或改变目标时读取。目标分析与授权由当前 Agent 判断；账本协议、候选选择与完成复审不因本文件改变，不新增执行模式或授权字段。

## 分析并展示提案

先只读恢复用户意图、可信快照与相关证据，展示以下五项供人工确认：

- 目标：PROJECT 的当前背景、本次预期结果、相关约束；优先复用已有项目，不为每个目标新建项目。
- 范围：CASE 的有界交付、验收与明确不做的内容；可以包含多个 CASE，说明它们与同一目标的关系。
- 已知缺口：各 CASE 的 GAP、证据要求、责任和真实依赖；已有事项与缺口引用权威标识，尚未注册的用提案标签，不冒充账本身份。
- 未知与风险：已知未完成义务、需调查的问题、范围外提示及可能需要人工决定的取舍。
- 执行边界：可自主决定的事项、必须再次确认的决定、资源限制与停止条件。

先理解结果再组织 PROJECT / CASE / GAP，不为凑齐层级或数量制造对象。初始 GAP 列表完整保留当前已知义务，不预测未知阶段链，也不承诺穷尽所有潜在工作。提案是待确认的工作模型，不是已接受的方案、项目决策或固定执行顺序；确认目标不代表提案中的未知已经解决。

授权未确认时只读分析，不创建事项、初始化或协调写回账本、不修改实现或事实载体。权威状态不可用时，展示不可用证据、可确认的信息及未知，说明初始化或恢复所需授权；不得为生成完整列表伪造快照。已有授权覆盖恢复时才通过可信入口处理，恢复后重新读取并校正提案。

## 确认与恢复

没有覆盖本次工作的明确执行授权时，展示提案并等待用户确认后启动。确认针对目标、范围、验收、自主决定与资源边界，不是逐个批准 GAP 或固定其顺序。沉默、旧缺口和 Agent 自己的提案都不是授权。

用户已明确授权分析并持续执行，或正在恢复已确认且未撤回的目标时，展示或简述恢复的授权依据与边界后继续，不重复请求确认。线程和宿主恢复信息可定位原始用户确认，但不是新增授权；恢复时找不到足以支持执行的授权依据，应只询问缺失的确认，不能靠 `next_responsibility: agent` 推导权限。

确认后才准备写入工作区、选择或创建事项并执行。新建事项只提交当前事实支持的初始缺口与真实依赖；账本分配身份，注册后重读快照，不预测 ID、修订号或候选令牌。用户确认可按现有事实与证据约定引用，不新建权威授权状态或绕过沙箱和破坏性操作审批。

## 动态调整而不重复审批

目标内必需的新发现、前置调查、回归修复与证据补齐可以在现有授权内形成候选，无需每新增一个 GAP 都问用户。拆分、合并、取消与替代按既有缺口边界及可信接口处理，保留原义务与依据；新增候选提交并重读后再比较，不能预选或顺带解决。

只有扩大交付范围、改变已确认验收、超出自主权限、接受重要风险或作必须由人决定的取舍时才请求新的确认。新证据使前置失效，不自动等于需要人工：先判断是否可在原授权内取证、纠正或重选。若请求的决定只阻塞部分工作，先推进其他独立且就绪的已授权 GAP。

## 持续执行与终点

当前 Agent 承担目标级循环：一个 GAP 完成或提交 `partial` 后，展示收尾、读取提交后快照，按[续轮门禁](round-boundary-contract.md#续轮门禁)重新比较并继续调用工具。账本轮次是状态转换边界，不是最终答复或 session 结束边界。

普通工作闭合后仍须完成 CASE 复审。一个 CASE 被账本接受为 `resolved` 后，检查同一授权目标中的其他 CASE 和未完成义务；只有目标验收及相关 CASE 复审均完成才能报告整个目标完成。无关项目缺口不扩大授权，也不阻止本目标结束。

暂停或终止必须说明具体条件、已有结果、未完成义务和恢复入口。用户停止、明确资源边界、实际人工或外部阻塞、无法在当前权限或能力下恢复的技术故障均如实保留，不伪造完成或人工业务决定。平台强制中断后的重新唤醒由宿主能力决定，技能文字不能保证 session 结束后自行重启。
