# 缺口选择流程

每轮选择下一缺口前读取；推理细则见[事项目标、缺口与必需保障](gap-reasoning.md)，选择字段见[缺口选择说明](selection-assessment.md)，展示与提交边界见[轮次边界契约](round-boundary-contract.md)。

## 识别相关义务

选择缺口前读取[事项目标、缺口与必需保障](gap-reasoning.md)，从原任务、用户增量、相关预期、当前事实、执行反馈、依赖与外部条件综合发现问题。同时逐项读取当前项目不变量目录的 `applies_when`、`must_hold`、`evidence_expectation` 与 `priority`，理解后显式说明各项在本事项的适用对象、依据和未决问题，作为选题依据之一。适用性包括尚未调查的必要预期与缺失，不从计划状态转换或准备修改哪些内容倒推。维度的数量、内容和证据责任完全来自动态读取的定义；`required` 表示必须考虑，不表示本轮清零或固定排序。

不变量不规定工作类型、技能、路径或执行顺序，也不等于必须更新某个载体。实际相关的长期判断不能静默遗漏：已有事实充分时显式确认，事实域无关时说明依据，相关但未解决时如实标记并由开放缺口承接，不为了让所有判断变成 `upheld` 而补做独立决策。

只有原任务验收必需、确实阻塞原任务或修复本次修改引入的回归时，缺失、过时、含糊、冲突或证据不足的结果才形成当前事项的开放缺口；独立问题作为提示，不因不变量检查扩大任务。既有结论不会永久豁免，后续事实可以重新威胁它并产生新缺口。

只有当前状态转换会对项目目标形成可接受结论时才记录影响。对实际相关目标的判断为：

- 已满足：`upheld` + 持久证据。
- 被威胁：`threatened` + 开放缺口。
- 证据不足：`undetermined` + 调查或澄清缺口。
- 不相关：不创建影响记录；但在本轮 `invariant_assessment` 中记录 `not_relevant` 理由。

## 先判断当前能否推进

按场景规则检查局部事实与共享依赖。问：剩余未知的不同答案，是否会改变本次结果、关键约束或验收标准？若会改变重要决定，先选择能区分答案的取证问题；若不影响本范围，说明依据并保留未知。前置未满足的候选先处理前置或交接，优先级不能绕过资格。将选择依据写入 `planned_transition.selection_assessment`，字段语义见[缺口选择说明](selection-assessment.md)。它区分探索与正式建立，并明确本轮验收及未决义务。

正式确立结论前，按[缺口推理说明](gap-reasoning.md)核对其中每项重要决定的来源、成立条件和未决依赖；目标明确不能替代智能体补充决定所需的依据。合并前检查内部依赖，不能把尚待取证的问题和依赖其答案的重要决定一起认定为可正式确立。

## 明确这一轮要成立什么

缺口表达尚未成立的具体结果，说明缺什么、成立后改变什么、何种证据足够。子结果共享目标、前提和验收边界时可以合并；若答案会改变后续方向、影响多个对象或需要独立取舍，则在这个判断处收紧边界。工作量、文件或测试数量不直接决定缺口数；大工作可以 `partial` 跨轮，小任务可只有一个普通缺口。遵守场景中的事实顺序与合并禁区。

## 比较候选并展示选择

根据本轮快照比较账本为全部活跃事项与项目派生的已持久化候选，以及当前上下文刚显露的新发现候选，在合格候选中选择最能解除当前目标关键阻塞、减少重大返工或产生直接价值的结果。影响面、不确定性、风险与依赖用于解释判断，不按陌生程度排序。选择前向用户展示独立的开轮说明：列出全部已持久化候选、实际发现的新候选、`selected`/`deferred`/`excluded` 与简短理由；不得声称穷尽了尚未发现的新工作。完整比较轨迹随状态转换保存，其中项目与选中事项范围由事项级选择令牌强绑定，以保留无关事项的并发推进。细则见[轮次边界契约](round-boundary-contract.md)。

## 普通工作闭合后选择复审

完成复审（Completion Review）是唯一显式语义自查，只在授权范围内的普通工作闭合后检查结果正确性、问题是否真实解决、验证可信度、回归风险与最小性。普通缺口的证据收集和确定性校验不是额外复审阶段。
