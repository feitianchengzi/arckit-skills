# 协议兼容性恢复

仅当可信账本兼容性探测返回 `incompatible` 时读取。协议恢复是权威账本的可读性恢复事务，不是项目推进，也不创建维护事项或普通缺口。

## 触发与分类

- `older_protocol`、`newer_protocol`、`unknown_protocol`、`missing_schema_version`：进入 `protocol_reconciliation`。
- `current_protocol_invalid`、`missing`、`unreadable`：进入 `current_protocol_repair`；不得把数据损坏伪装成版本升级。
- `compatible`：不得进入恢复模式，直接执行正常事项循环。

宿主只传递兼容性、受影响引用、预期模式与快照令牌；它不选择转换策略。运行时可以提供由能力清单解析的绑定；直接调用的 Codex 未收到绑定时，智能体从已加载或已安装的 `arckit-development-ledger` 能力清单解析 `loop_snapshot` 与 `protocol_compatibility`，使用同一可信脚本。智能体必须读取受影响的权威记录、当前模式与权威定义、相关长期事实和必要源码，理解旧字段承载的真实语义。

## 智能体责任

形成 `arckit-protocol-reconciliation/v1` 候选替换记录。转换应满足：

- 保留可映射的项目意图、事项与迭代身份、已接受事实、证据、开放工作、问题、影响和交接；不静默关闭或删除义务。
- 新协议要求但旧状态没有证据的内容保持开放或未知，不编造项目事实。
- 权威核心决策领域与软件不变量精确使用当前协议定义；项目具体结论仍放在决策或事实中，不得伪装成不变量。
- 协调转换只恢复协议可读性，不顺带推进普通事项工作、解决普通缺口或完成复审。
- 每个替换记录写明语义依据；仍有不能可信映射的不确定性时不得提交可信写回，应按真实责任交接。

智能体不直接编辑权威账本。以当前授权工作区根目录为工作目录，使用 `arckit-development-ledger` 能力清单声明的可信入口和契约引用执行 `read`、`probe`、`validate` 与 `reconcile`；不得假设目标业务仓库包含 Arckit 源码相对路径，也不得要求先注册事项。标准输入或临时 JSON 只是传输方式，不是持久证据。

## 成功与停止

可信入口使用快照令牌和来源摘要防止并发覆盖，校验当前模式、跨记录引用和保真边界，并在项目锁内原子更新记录与投影。成功后必须重新调用 `loop_snapshot`；只有新回执为 `available` 才继续原始用户事项，不得复用恢复前的修订号、候选或授权判断。

只有这些情况停止自动恢复：存在无法从事实判断的语义映射、可能丢失义务、需要人类接受风险，或受影响权威内容无法安全重建。报告受影响引用、已确认事实、未决映射和恢复所需的最小输入。
