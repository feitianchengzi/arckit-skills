# 缺口执行与证据

选中缺口后、开始执行前读取；新证据要求重定边界时，结合[缺口推理说明](gap-reasoning.md)处理。

## 工作到当前结果成立或需要重新决定

围绕选中缺口的结果动态使用必要技能和工具。调查、比较、试验可用于证明当前结果；证据足够时验收，未足够则保留 `partial`。若需要另行选择的独立结果或重要决定首次具备条件，或新证据使已接受预期、关键前提、责任或验收边界需要重定，保存当前证据及义务，提交并重新读取最新状态后重选。同一验收内的动作依赖就绪、约束内的方法调整与常规排障可继续；独立因果问题按场景规则处理。不因探索标签自动换缺口，也不以实验存在宣称正式兑现；关键前置缺失仍先取得依据。

专业技能是独立可复用能力，不是不变量的一一对应执行模块。智能体依据当前目标选择并读取其方法，在授权与选中缺口边界内使用；专业技能包含的后续流程不自动扩大本轮目标。若其必要步骤与当前边界冲突，显式报告冲突和剩余义务，不能静默越界或跳过方法门禁。

## 处理新事实

新事实用于理解、解决或验证当前选中的缺口时，可以在本轮继续使用；暴露另一个独立缺口时，只记录事实与必要候选，不顺带解决。当前缺口解决后提交并重新读取最新状态，再独立选择下一缺口；需要用户决定时交接人工。

新证据涉及已有主张时，按[缺口推理说明](gap-reasoning.md)核对具体主张及其条件，区分用户目标与智能体补充的决定。说明哪些仍成立、哪些需调整、哪些尚未知，并重审依赖它们的缺口资格；“目标没变”不能替代这项核对。

若新事实证明既有缺口过宽或前提失效，按[缺口推理说明](gap-reasoning.md)的重新界定规则保留未完成义务，通过可信接口记录取消或替代后重新读取最新状态并重选；不把取消宣称为完成，不为续轮换号。

## 维护已建立的结论

全面理解相关事实与判断不变量，不等于本轮补齐全部预期事实。只建立解决选中缺口所需的新结论；同一有界结论集合可以同步多个事实载体；相关低风险结论可以共同建立，独立重要决策与场景规定不可合并的结论必须分开。

结论形成或改变的当轮维护对应事实载体，优先更新已有文档。新反证须重审全部实际相关判断，明确哪些旧主张失效或仍有依据；不以文件存在、测试数量或某一问题已修复支持其他未决主张。

## 无领域技能时维护事实源

项目未安装对应 definition 技能时，仍按同一缺口边界维护事实：

- 从 `arckit/_kit/<domain>/` 复制模板创建或更新文档；项目已有 `arckit/<domain>/CONVENTIONS.md` 时优先遵循项目约定和现有目录。
- 按 `arckit/_kit/CONVENTIONS.md` 维护 INDEX、行数标注、探索隔离与归档；模板默认值不是已确认事实。
- 结论按该文件的“结果映射”写入 `facts_added`、`software_definition_changes`、`invariant_assessment` 和 `evidence`，不新增 `fact_result` 协议字段。
- 缺少技能不降低证据与恢复性责任；无法形成的独立结论保留为开放缺口。

## 结果验证前确定证据上下文

检查结果是否符合明确预期时，在运行会产生验证文件的工具或脚本前，读取 `arckit-development-ledger` 的 `references/case-evidence.md`，明确待验证主张、已确认的事项身份、本次运行输出目录及保留方式，并将其作为当前执行上下文供所选技能和工具使用。区分交付物、可复用验证源码与本次运行证据；路径不决定事实角色。当前软件适配器的证据根为 `arckit/cases/evidence/<case-id>/`，具体组织、读取核验、引用和清理由该约定承载。已有事实载体直接引用，不新增重复报告；结果验证工具的默认输出位置与当前上下文冲突时先调整输出配置，不能等产物散落后再决定归档。此上下文由同一智能体维护，不新增运行时路由或状态协议。
