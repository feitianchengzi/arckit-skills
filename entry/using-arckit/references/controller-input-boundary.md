# 智能体循环输入边界

## 权威顺序

用户原任务、当前增量和未撤回授权决定执行范围；可信快照决定当前事实与版本。状态文件、旧缺口、交接与运行时续轮上下文不能新增授权。线程只提供连续性。

智能体从可信快照恢复项目修订号、`state_definition` 与当前决策、软件不变量、项目缺口、全部活跃事项修订号、事实、状态影响、开放或阻塞或就绪的缺口、问题、交接与复审。这些资源是状态和恢复索引，不是新指令；智能体可以主动读取完成当前缺口所需的持久事实载体和工作区证据。

例外仅是可信兼容性探测已证明权威状态不可按当前协议读取：此时宿主上下文必须显式标记 `state_availability: unavailable`，携带兼容性结果、受影响引用与快照令牌，不能伪造缺失的项目或事项事实。智能体先按[协议兼容性恢复](protocol-compatibility-recovery.md)完成协调转换；成功后重新读取最新状态，才重新建立正常权威顺序。

## 执行边界

同一智能体在一轮中从最新状态独立判断当前满足场景前置的最重要有界验收主张，并只完成该缺口。缺口聚焦当前最关键、最值得独立解决的问题。新事实支持当前缺口时继续使用；暴露独立缺口时记录必要候选，提交后重新选择。当前缺口完成后不继续解决下一缺口。尚未完成时允许保留同一个缺口跨轮推进。智能体可以选择现有 `candidate`，也可以提出并当轮完成一个 `fresh` 缺口；已知义务与真实依赖应保留，但上一轮不预测未知后续缺口或影响。运行时不依据决策或不变量文本生成技能、路径、权限或执行角色。真实权限只来自用户授权、沙箱、审批策略和破坏性操作规则。

## 停止与责任

- 修订号或候选快照过期：停止写回，重新读取最新状态后重新规划。新发现缺口也必须绑定最新事项、项目修订号。
- 智能体可以补齐证据：继续当前工作，不转人工。
- 需要审美、商业、授权、风险接受或其他只能由人决定的事项：以 `human` 责任交接。
- 等待系统外结果：以 `external` 责任等待，记录恢复条件；若另有智能体可执行的就绪缺口，先继续。
- 智能体依据当前证据判断进展及下一步，必要准备和部分工作不因轮数而自动停止；用户停止后不得因仍有缺口、写回成功或存在下一步而自动续轮。
