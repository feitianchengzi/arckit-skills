# Arckit App Store 交付

仅调用 `$arckit-appstore-delivery` 即执行默认任务：让当前项目对应提交的构建进入内部 TestFlight 测试组，并邀请有应用权限的合格组织成员。

## 默认契约

- 这是显式调用入口，不因提到 iOS、证书或 Git 就自动执行。附加要求可缩小范围；仅咨询时不写入。
- 默认范围包含必要的项目配置、Apple 资源创建/复用、Xcode Cloud 配置、交付所需改动的提交、向当前已确认远端分支推送及版本标签推送、构建追踪、内测入组和邀请。
- 开始时简短声明范围并继续，不要求用户再写任务描述。具体团队、应用、远端或交付目标不唯一时先做独立准备，再问最少的问题。
- 保留用户明确授权；宿主命令批准与 Apple API 权限分别处理。本文件不能绕过宿主审批，也不能补充超出默认契约的授权。
- 正式审核/上架、外部测试、法律协议接受、证书吊销、权限扩张、强推、移动既有标签、切换/创建/合并分支均需额外明确授权。
- 复用已有资源；任何创建前查询，写入后回读。写请求超时先对账，不直接重放。
- 不自动升级应用主次版本、不提交无关改动、不把工作区“最新”或后台“最新”当作本次交付证据。
- 密钥不进入仓库、聊天或日志；只记录凭据引用。加密合规结论结合实现证据判断，不能由脚本猜测。

## 1. 发现项目与恢复任务

输入：当前目录、会话指令、项目已有记录。
动作：读取适用的 `AGENTS.md`、Git 状态、工程/工作区、主应用与扩展构建目标、构建方案、版本和签名设置；读取 [发现与状态](references/discovery-state.md)。
- 查找已有交付配置、CI 和版本规范，优先复用。多应用/多仓库歧义必须解析，不拿第一个结果代替选择。
- 识别首次配置、续接或新增交付；再次调用先查询已记录资源和云端状态。
- 当前提交已达到终点时输出现状，不再消耗证书、标签或构建。
退出：发布单元、代码来源、默认目标和待补输入确定；记录允许的操作范围。

## 2. 验证 Apple 连接

输入：团队信息、现有凭据引用。
动作：读取 [授权与人工交接](references/auth-handoff.md)，验证凭据和可访问资源，不靠 Key ID 猜团队。
- 优先使用项目已配置工具；无合适工具时使用附带的 Node API 客户端。
- 缺少密钥、团队选择、登录/2FA、协议或仓库授权时，提供具体页面、字段和完成后的验证动作。
- 用户回复“完成”后重新查询；失败区分宿主拒绝、请求未发起、网络、401、403 和业务错误。
退出：目标团队明确，必要 API 可访问；否则保存事实和最小人工动作。

## 3. 补齐应用身份和签名

输入：平台、构建目标、团队、现有资源。
动作：读取 [身份与签名](references/signing.md)，按真实需求复用/创建 Bundle ID、应用能力和预置描述文件；只创建缺失且必要的证书。
- 检查本地证书与私钥配对、有效期、平台用途；Xcode Cloud 管理签名与本地签名分开判断。
- 新建 App Store Connect 应用采用官方网页流程；可用浏览器先准备/填写，仅无法自动完成的环节交给用户。
- 从已确认命名规则或用户前缀生成 Bundle ID；缺少依据时问一次，不虚构企业域名。
退出：应用、Bundle ID、团队匹配；签名满足本地开发和目标分发需要。

## 4. 配置项目和 Xcode Cloud

输入：已匹配身份、项目、仓库。
动作：读取 [Xcode Cloud 与版本](references/cloud-version.md) 和 [TestFlight 与合规](references/testflight.md)。
- 修改生成源或原生工程；保留已有配置，验证共享构建方案、授权配置、版本和构建号。
- 检查应用及依赖加密用途，有依据时配置 `Info.plist`；不为消除提示盲设豁免。
- 查询 Xcode Cloud 产品、仓库、工作流；配置版本触发归档、必要验证动作和内部测试分发。
- API 未覆盖的首次接入/后置操作用浏览器或精确人工交接补齐；区分用户确认与 API 回读证据。
- 运行必要的配置、编译/归档检查；复用有效证据，不为验证重复签发证书或上传产物。
退出：本地配置可用，远端触发与构建方案对齐，分发路径明确。

## 5. 创建唯一交付触发

输入：已验证配置、项目 Git/标签规范。
动作：按 [Xcode Cloud 与版本](references/cloud-version.md) 的基线和幂等规则，显示目标分支、SHA、远端、标签，执行默认契约内的最小提交/推送。
- 既有 Git 规范优先，无需隐藏加载另一个技能。无规范时采用引用文档中的默认值。
- 原有未提交改动必须说明归属；仅提交本次必要且范围明确的文件，不默认暂存全部文件。
- 当前分支无法满足既有稳定线策略时准备方案并询问分支操作，不自动切换。
- 标签已存在且同 SHA 时查询构建；异 SHA 时处理冲突，绝不覆盖。
退出：远端标签/提交已核实，记录触发时间，开始定位对应 Xcode Cloud 运行。

## 6. 追踪构建、入组并邀请成员

输入：工作流、标签、SHA 和构建关联。
动作：按照 [Xcode Cloud 与版本](references/cloud-version.md) 追踪本次运行，按照 [TestFlight 与合规](references/testflight.md) 完成声明、入组和成员去重。
- 用运行 → 构建关联选择产物，核对应用、平台、版本及处理状态，不能仅按上传时间取第一条。
- 可测试后加入内部组，按既有名单或默认合格组织成员范围邀请，不扩大组织权限。
- 短轮询并保持进度可见。超出等待窗口则保存恢复点、报告待处理，不声称完成。
退出：本次构建在组内且可内测；成员已加入且邀请状态已回读，或阻塞可恢复。

## 7. 交付与恢复记录

输入：各阶段本地/远端证据。
动作：更新 [发现与状态](references/discovery-state.md) 规定的配置和本地状态；后续调用重新读取远端事实。
退出：输出应用/团队、版本（构建号）、SHA/标签、工作流/运行、测试组、成员数量及跳过原因、合规状态、验证证据和剩余人工动作。
- 区分已配置（`configured`）、已触发（`triggered`）、处理中（`processing`）、已就绪（`ready`）、已邀请（`invited`）、已接受（`accepted`）；已邀请不等于已安装。
- 完成表示内部测试可用，不表示正式审核通过或上架。
