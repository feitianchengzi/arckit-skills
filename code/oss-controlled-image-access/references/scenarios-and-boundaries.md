# 场景和边界

## 真实使用场景

1. 用户在服务端仓库中说：“用这个技能带我实现 OSS 图片可控访问。”
   - 智能体先扫描服务端配置、路由和图片 URL 生成逻辑。
   - 智能体直接实现图片网关、OSS 签名服务和业务接口 URL 输出。
   - 智能体在需要 OSS 端点、Bucket、AccessKey 配置时让用户配置到安全位置。

2. 用户在客户端仓库中说：“服务端要改成图片网关，我这边要怎么配合？”
   - 智能体不实现 OSS 签名。
   - 智能体查找 API 服务、URL 归一化函数、图片加载、缓存、分享页和 `og:image` 代码。
   - 智能体删除或替换公开 OSS/CDN 基础 URL 拼接，例如 `VITE_OSS_PUBLIC_BASE_URL`。
   - 智能体确保客户端把稳定网关 URL 当不透明字符串使用，并验证或说明 302 跟随和签名 URL 不持久化。

3. 用户在同时包含服务端和客户端的仓库中说：“一步一步帮我接起来。”
   - 智能体先改服务端，再修改或验证客户端。
   - 智能体尽量做端到端最小验证。
   - 智能体不在客户端迁移完成前建议 Bucket 私有化。
   - 智能体最后输出人类需要完成的云资源和私有化步骤。

4. 用户在运维仓库中说：“帮我把部署配置补好。”
   - 智能体补环境变量模板和密钥说明。
   - 智能体先判断部署形态和入口拓扑，避免把镜像包部署误当源码构建。
   - 智能体不要求用户立刻把 Bucket 改私有。
   - 智能体把 Bucket 私有化放到最后发布门禁。

5. 用户只在文档仓或空目录中说：“我不知道怎么开始。”
   - 智能体输出接入契约、跨仓步骤、人类操作清单和验收计划。
   - 智能体不假装已经改完服务端或客户端。

6. 用户在上线排障中贴出 `404`、`502`、`SignatureDoesNotMatch`、`lstat /core-service`、容器名冲突或 Caddy/nginx/API Gateway 配置。
   - 智能体先判断错误属于部署、入口网关、网络、HTTP 方法、RAM/STS 签名还是 OSS 权限。
   - 智能体按后端本机、入口机到后端、公网域名、浏览器/客户端的层次验证。
   - 智能体不把所有问题都归咎于 OSS 或 RAM。

7. 用户说：“后端网关通了，接下来前端/客户端怎么改？”
   - 智能体读取客户端迁移参考文档。
   - 智能体先检查业务接口实际返回的图片字段，再检查客户端是否二次拼接 OSS/CDN 基础 URL。
   - 智能体覆盖列表、详情、头像、上传预览、分享页、SSR/OpenGraph、缓存和构建环境变量。
   - 智能体输出客户端验证证据或跨仓交接清单，不把后端 302 成功当成全链路完成。

## 适用边界

使用本技能：

- 从 OSS 公开直链迁移到服务端可控访问。
- 实现或设计稳定图片网关 URL。
- 服务端生成短时 OSS GET 签名 URL。
- 客户端或分享页配合网关图片加载。
- 前端/客户端从公开 OSS/CDN 基础 URL 拼接迁移到稳定网关 URL 消费。
- 规划 RAM 权限、部署环境变量、密钥管理、Bucket 私有化顺序。
- 初版先不用 CDN，后续可升级 CDN。

不使用本技能：

- 只问 OSS 或 CDN 价格对比。
- 只做通用 DDoS、安全科普，不涉及项目接入。
- 只需要阿里云控制台手工操作且不需要代码、配置或跨角色协作。
- 已明确采用完全不同架构，例如后端代理全部图片流量且不使用 OSS 签名。

## 默认假设

- 初版目标是“先跑通流程，再切私有”。
- 图片主要是封面、头像、分享页图片等可展示资源。
- 数据库理想状态保存 OSS 对象键，而不是永久公开 URL。
- 客户端可以跟随 HTTP 302；若是原生客户端、小程序或特殊图片库，需要实测。
- 服务端业务接口是客户端最终契约来源；前端最好不需要知道网关基础 URL，除非为历史对象键做过渡兼容。
