# 功能设计

## 从需求到代码结构

实现 SwiftUI 功能前，先把需求压成可编码结构：

- 用户入口：页面进入、外部链接、Widget、推送、分享回流或系统选择器。
- 用户动作：点击、输入、刷新、提交、取消、重试、切换权限或离开页面。
- 数据来源：本地、远端、缓存、系统能力、App Group、生成服务或用户输入。
- 页面状态：空闲、加载中、成功、空数据、错误、提交中、已取消、权限拒绝。
- 成功结果：展示、落库、刷新、跳转、分享、通知其他页面或更新 Widget。
- 失败结果：用户可理解文案、重试入口、降级内容、日志分类和恢复路径。

## 状态矩阵

新页面或复杂功能至少判断这些状态是否存在：

| 状态 | 判断 |
| --- | --- |
| 加载中（loading） | 首次加载和手动刷新是否区分 |
| 空数据（empty） | 空数据是正常状态还是错误回退 |
| 错误（error） | 网络、权限、业务错误、解析失败是否需要不同处理 |
| 成功（success） | 数据是否可能部分完整、过期或来自缓存 |
| 提交中（submitting） | 是否需要禁止重复提交或允许取消 |
| 过期（stale） | 参数变化或页面消失后旧任务是否可能写回 |

不要用多个松散的 `Bool` 表达互斥状态；用 `enum` 或稳定状态模型表达页面核心状态。

## 导航与外部入口

Route 使用稳定的 `enum`/`struct`，只携带 ID 和必要上下文，不传大对象、DTO 或 View。深层链接、Universal Link、Widget、推送和分享入口进入统一解析器，再转换为 Route。解析失败要有回退和日志分类。

外部入口和应用内入口进入同一业务目标时，必须得到等价的资源身份、展示模型、权限状态和主操作能力。不能只验证“能打开页面”；外部入口只有 ID 时，目标页面需要等价补全路径或明确降级状态。

## 完成口径

功能完成要求主路径、失败路径、取消或重复操作、空数据和权限态都有明确的代码位置和验证方式。
